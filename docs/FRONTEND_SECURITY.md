# Frontend Security

## 🔒 Security Fixes Applied

### Critical: Token in URL Path (FIXED)
**Issue**: Encrypted Plex tokens were being passed as URL path parameters:
```
❌ GET /api/setup/plex/servers/{encrypted_token}
```

**Impact**: 
- Tokens visible in browser Network tab
- Tokens logged in server access logs
- Tokens stored in browser history
- Even though encrypted, this violates security best practices

**Fix**: Changed to POST with token in request body:
```
✅ POST /api/setup/plex/servers
   Body: { "auth_token": "encrypted_token" }
```

**Files Changed**:
- `backend/app/api/routes/setup.py` - Changed GET to POST endpoint
- `frontend/src/pages/Settings.tsx` - Updated to use POST
- `frontend/src/pages/SetupWizard.tsx` - Updated to use POST
- `backend/tests/test_setup_routes.py` - Updated test

## Browser Network Tab Token Exposure

### ⚠️ IMPORTANT: Not All "Tokens" Are Security Issues!

When viewing Deduparr in your browser's Network tab, you **will** see requests with `?token=` parameters. **This is normal web development behavior** and most are NOT security concerns.

#### ✅ COMPLETELY SAFE - Vite HMR WebSocket (Development Only)

```
ws://127.0.0.1:3000/?token=_6R-0T38W3rd
ws://127.0.0.1:3000/?token=abc123xyz789
Sec-WebSocket-Protocol: vite-hmr
```

**This is NOT sensitive data!** 
- ✅ **Only in development** - Disappears in production (`npm run build`)
- ✅ **Random token** - Generated by Vite for each dev server session
- ✅ **No access to data** - Only used for hot module replacement (auto-reload)
- ✅ **Cannot be disabled** - This is how Vite works, and it's perfectly safe
- ✅ **Not your Plex token** - Has nothing to do with your media server

**You can ignore this completely!** Every React/Vue/Svelte developer sees these in dev mode.

#### ⚠️ SENSITIVE - Plex Media Resources (Production & Development)
```
GET https://plex.server/library/metadata/123/thumb?X-Plex-Token=xyz123
GET https://plex.server/photo/:/transcode?X-Plex-Token=xyz123
```

**This IS your Plex authentication token!** This token:
- Grants access to your Plex Media Server
- Appears when loading posters, thumbnails, video streams
- Is unavoidable due to Plex API design (see below)

### Plex Media Thumbnails & Resources

**IMPORTANT**: You may see URLs with `?token=` parameters in your browser's Network tab when viewing Plex media. **This is expected and unavoidable** - it's how Plex authenticates media requests (posters, thumbnails, transcoded streams, etc.).

Example:
```
GET /library/metadata/12345/thumb/123456789?token=_6R-0T38W3rd
```

#### Why this happens:
1. **Plex API Design**: Plex Media Server requires authentication tokens in URLs for media resources
2. **Third-party URLs**: These are direct URLs to your Plex server, not our backend
3. **Browser Behavior**: All network requests are visible in DevTools - this is by design

#### Is this a security risk?
- ✅ **Tokens are encrypted** in our database using `itsdangerous` 
- ✅ **Tokens are short-lived** and can be revoked via Plex
- ✅ **Only visible to you** in your own browser DevTools
- ✅ **Console output is sanitized** in production builds (see below)
- ⚠️ **Don't share screenshots** of Network tab with tokens visible

#### Mitigation:
Our frontend security layer prevents tokens from appearing in:
- Console logs (production mode only)
- Error messages
- Debug output
- Analytics/telemetry

However, we **cannot hide** tokens that appear in browser DevTools Network tab - this is a fundamental limitation of how browsers work.

### What IS Protected

Our security utilities (`src/lib/security.ts`) protect against:

1. **Console Log Exposure**: All `console.log/warn/error` calls are sanitized in production
2. **Request Logging**: API keys, tokens, passwords are redacted
3. **Error Messages**: Sensitive data is stripped from error objects
4. **Debug Output**: Development tools don't leak credentials

## Security Best Practices

### For Developers

1. **Never log tokens directly**:
   ```typescript
   // ❌ BAD
   console.log('Token:', authToken);
   
   // ✅ GOOD  
   import { sanitizeLogData } from '@/lib/security';
   console.log('Token:', sanitizeLogData(authToken));
   ```

2. **NEVER put tokens in URLs** (fixed in latest version):
   ```typescript
   // ❌ BAD - token visible in browser history & Network tab
   fetch(`/api/servers/${token}`);
   
   // ✅ GOOD - token in request body
   fetch('/api/servers', {
     method: 'POST',
     headers: { 'Content-Type': 'application/json' },
     body: JSON.stringify({ auth_token: token }),
   });
   ```

3. **Use POST for sensitive data**:
   ```typescript
   // ❌ BAD - credentials in URL query params
   axios.get(`/api/auth?token=${token}&password=${pwd}`);
   
   // ✅ GOOD - credentials in request body
   axios.post('/api/auth', { token, password });
   ```

4. **Sanitize URLs before logging**:
   ```typescript
   import { sanitizeUrl } from '@/lib/security';
   console.log('Request URL:', sanitizeUrl(url));
   ```

### For Users

1. **Don't share screenshots** of browser DevTools Network tab
2. **Revoke Plex tokens** if you suspect compromise (Settings → Devices in Plex)
3. **Use HTTPS** when accessing Deduparr remotely
4. **Keep tokens private** - they grant full access to your media
